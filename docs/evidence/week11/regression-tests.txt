

  Voting - 멀티시그 / 비상정지 / 투표 무결성
    1. 접근 제어 (OWASP SC01)
      √ 관리자가 아닌 계정은 propose/approve/후보등록을 할 수 없다
      √ 관리자가 1명일 때 2번째 관리자 추가는 예외적으로 즉시 반영된다
      √ 관리자가 2명이면 3번째 관리자 추가는 2명 승인이 있어야 반영된다
      √ 최초 관리자(admin)는 제거할 수 없다
    2. 멀티시그 동작 (제안 → 승인 → 실행)
      √ 관리자 1명의 제안만으로는 선거가 시작되지 않는다 (승인 1/2)
      √ 두 번째 관리자가 승인하면 실행된다
      √ 같은 관리자가 같은 제안을 두 번 승인할 수 없다
      √ 이미 실행된 제안은 다시 승인/실행할 수 없다
      √ 제안 시 제안자의 승인 1표가 자동으로 들어간다
    3. 비상 정지 (Emergency Stop)
      √ 강제종료는 2명 승인 후에만 실행되고, 이후 투표가 차단된다 (38ms)
      √ 정지 상태에서도 확정 전 getWinner() 조회는 거부된다
      √ 재개(Resume)도 2명 승인이 필요하고, 재개 후 다시 투표할 수 있다 (42ms)
      √ 진행 중이 아닌 선거는 강제종료할 수 없다
    4. 투표 무결성
      √ 미등록 유권자는 투표할 수 없다
      √ 1인 1표: 같은 유권자의 중복 투표는 거부된다
      √ 존재하지 않는 후보에는 투표할 수 없다
      √ 선거 시간이 지나면 투표가 거부되고, 결과 확정 후 당선자를 조회할 수 있다 (39ms)
      √ 진행 중에는 당선자를 조회할 수 없다
    5. [7주차 보완 검증] 선거 시작 후 등록 차단 (V-A, V-B)
      √ 선거 시작 전에는 유권자·후보 등록이 정상적으로 된다
      √ V-A 방어. 선거 시작 후 관리자 1명이 유권자를 추가 등록하려 하면 거부된다
      √ V-B 방어. 선거 시작 후 관리자 1명이 후보를 추가하려 하면 거부된다
      √ 강제 종료(정지) 상태에서도 등록은 차단된다 (82ms)
      √ 선거가 끝난 뒤에도 등록은 차단된다 (선거 1회용 정책)
    6. [7주차 보완 검증] 결과 확정 finalize() (타임스탬프 문제, V-F)
      √ 선거가 진행 중이면 확정할 수 없다
      √ 선거를 시작한 적이 없으면 확정할 수 없다
      √ 종료 후에는 관리자가 아닌 계정도 확정할 수 있고, 당선자가 저장된다 (49ms)
      √ 확정은 한 번만 가능하다
      √ 확정 후에는 시간이 더 지나도 조회 결과가 변하지 않는다
      √ 확정하면 ResultFinalized 이벤트가 기록된다 (39ms)
      √ 비상 정지 중에는 확정할 수 없다
      √ 확정된 뒤에는 선거를 다시 시작할 수 없다
      √ V-F 방어. 후보가 없으면 확정이 의미 있는 메시지로 거부된다
    7. [8주차 보완 검증] 이벤트 로깅 (진단 No.5)
      √ 제안하면 ProposalCreated와 제안자의 ProposalApproved(1표)가 기록된다
      √ 두 번째 승인으로 실행되면 ProposalApproved(2표), ProposalExecuted, ElectionStarted가 기록된다
      √ 관리자 추가·제거가 AdminAdded / AdminRemoved로 기록된다
      √ 강제 종료·재개가 EmergencyStopped / Resumed로 기록된다 (by = 실행을 완료한 승인자)
      √ 유권자 등록이 VoterRegistered로 기록되고, 이미 등록된 주소는 다시 기록되지 않는다
      √ 후보 추가가 CandidateAdded로 기록된다
      √ 투표가 Voted(투표자, 시각)로 기록된다
      √ Voted 이벤트에는 후보 정보가 없다 (거래 입력 공개와 별개로 이벤트의 정보 최소화)
    8. [8주차 증거 보강] 멀티시그 (진단 No.3, No.4)
      √ No.4. 관리자 제거도 2명 승인이 있어야 실행된다 (1명 제안만으로는 제거되지 않음)
      √ No.3. 관리자 3명이면 최초 관리자 없이 나머지 2명의 승인만으로 비상 정지를 실행할 수 있다
    9. [9주차 보완 검증] 관리자 인원 무결성 및 선거 1회 제한
      √ V-C. 첫 관리자만 있을 때 자신을 다시 추가해도 인원이 늘지 않는다
      √ V-C. 0주소를 관리자로 추가할 수 없다
      √ V-C. 중복 추가 실행이 거부되고 승인·실행·인원 상태가 되돌아간다
      √ V-C. 같은 주소의 추가 제안이 겹쳐도 두 번째 실행 시점에 차단된다
      √ V-D. 비관리자 제거로 인원 감소·단독 추가 예외가 열리지 않는다
      √ V-D. 실제 관리자를 제거하더라도 2명 미만으로 줄일 수 없다
      √ V-D. 제거 후 정상 재추가하면 실제 구성원 수와 인원 수가 일치한다
      √ V-D. 제거 제안이 겹쳐도 이미 제거된 주소로 인원을 다시 줄이지 못한다
      √ V-E. 진행 중 재시작으로 종료 시각을 바꿀 수 없다
      √ V-E. 정지 상태에서 시작 제안으로 정지를 우회할 수 없다
      √ V-E. 종료 후 확정 전에도 재시작을 막고 득표·투표 기록을 보존한다
      √ V-E. 시작 전에 만든 두 제안도 하나만 실행할 수 있다
      √ 시작 시간 0분을 거부하고 유효한 새 시작 제안은 실행할 수 있다
    10. [10주차 보완 검증] 동점·0표 및 결과 조회 정책
      √ V-G 방어. 동점이면 등록 순서로 당선시키지 않고 당선자 없음으로 확정한다
      √ V-G 방어. 모두 0표이면 첫 후보를 당선시키지 않고 투표 없음으로 확정한다
      √ V-G 방어. 후보가 한 명이어도 0표이면 당선자가 없다
      √ 후보 한 명이 실제 득표하면 정상 당선으로 확정된다
      √ 앞선 후보가 동점이어도 뒤 후보가 더 많이 득표하면 단독 당선이다
      √ 낮은 득표 후보가 있어도 최다 득표가 같으면 동점으로 기록된다
      √ 당선자 없음도 최종 확정이며 재확정·재시작·사후 정지로 바꿀 수 없다
      √ 확정 전 결과 상태는 Pending이며 getWinner 조회는 거부된다
      √ No.15 방어. 외부 계정이 정지 중 미확정 선두 후보를 조회할 수 없다
      √ No.15 방어. 관리자도 미확정 조회를 우회하지 못하며 재개 후 확정해야 공개된다
